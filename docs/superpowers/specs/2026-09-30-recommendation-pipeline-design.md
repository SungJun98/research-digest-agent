# 추천 파이프라인: PaperFlow를 참고한 수정 설계

작성일: 2026-09-30 · 상태: 사용자 승인으로 확정 · 제품 코드 구현 전

## 목적과 접근

관련 논문을 많이 전달하기보다, 오늘 읽을 가치가 높은 3~5편을 설명과 함께 고른다. 중요도·기여·연구계 관심을 함께 보며, 기존 연구와 닮았다는 이유로 추천하지 않는다. 관심 주제와 추천 기준은 사용자가 바꾼다.

추천 접근은 **PaperFlow의 흐름을 참고하는 독립 모듈 구성**이다. 의미 기반 후보 검색, 개인 관련성의 최소 기준, 다양성 재정렬, 명시적 피드백 기록을 참고한다. 전체 포크는 GUI·Wiki·봇 등 첫 버전 밖의 기능까지 유지해야 하므로 선택하지 않는다. 단순 키워드 추천은 중요한 새 방향을 놓칠 수 있으므로 최종 판단에 사용하지 않는다. 실제 코드를 재사용할 때는 해당 모듈·라이선스·테스트를 확인하고 출처를 남긴다. 현재 코드 복사나 포크는 하지 않았다.

## 사용자 관심과 평가 관점

초기 관심은 아래의 넓은 주제로 구성한다. safety와 reasoning의 초기 우선순위는 3, 나머지는 2이며 모두 수정 가능하다. 이 값은 후보 검색과 개인 관련성에 반영한다. 기준 미달 논문을 통과시키지는 않는다.

| 주제 | 포함하는 문제 |
| --- | --- |
| AI safety & alignment | 위험·실패 평가, 감독과 제어, 견고한 정렬, reward hacking, preference optimization의 실질적 정렬 문제 |
| Reasoning & decision-making | 추론 신뢰성, 검증·탐색·다중 후보 비교, agent 의사결정, 적응적 계산과 test-time scaling |
| Learning & generalization | 학습 원리, 불확실성, 일반화·전이·분포 변화, 확률적 학습 |
| Interpretability & model behavior | 내부 메커니즘, 설명의 충실성, 행동의 인과 분석, 실패 원인과 개입 |

홈페이지의 연구 철학에 맞춰 **불확실성 아래 신뢰할 수 있는 판단**, **변화하는 조건에서의 견고성**, **데이터·계산 효율**을 개인 관련성의 평가 관점으로 쓴다. 모든 후보에 uncertainty라는 단어를 요구하지 않는다. GAE·Train for Many 등 본인 논문과의 유사도는 기본 검색·추천 점수에 넣지 않는다. 해당 논문은 명시적으로 팔로우했을 때 후속 연구 추적에 사용한다.

Diffusion language model의 decoding만 다루는 연구와 작은 설정 변경 위주의 연구는 기본적으로 낮은 우선순위다. preference optimization은 alignment 안에 포함하며, 학습 목표·감독·견고성에 실질적인 기여가 있는지 본다. 넓은 문제에 기여하는 연구를 방법 이름만으로 배제하지 않는다.

## 추천 흐름

**수집 → 후보 압축 → 관련성 확인 → 읽을 가치 평가 → 상위 후보 근거 확인 → 다양성 선정 → 설명·전달 → 명시적 피드백**

| 단계 | 구체적인 처리 | 결과 |
| --- | --- | --- |
| 1. 수집·정규화 | arXiv·HF Daily Papers·Scholar 메일 수집, DOI/arXiv/S2 ID 연결, 이미 전달한 논문 제외. 기본 최근 72시간, 복구 수집 최대 7일 | 신규 논문 풀과 출처 기록 |
| 2. 후보 압축 | 주제 설명과 제목·초록의 의미 유사도로 주제별 상위 10편. 추가로 관측된 관심이 높은 후보·인접 주제 후보 최대 10편. 합집합 최대 50편 | 특정 주제에 몰리지 않는 평가 목록 |
| 3. 관련성 확인 | LLM이 해결하려는 문제와 설정 주제의 관계·제외 사유를 판정. 관련성 3/5 미만 또는 명시적 제외 주제이면 탈락 | 통과/탈락 사유 |
| 4. 읽을 가치 평가 | 중요도·기여 근거·관심 신호·개인 관련성을 평가. 판단에 사용한 문장과 신호를 저장 | 점수와 근거 |
| 5. 근거 보강 | 잠정 상위 최대 8편의 공개 HTML이 있으면 서론·결과·한계·결론의 관련 부분을 최대 8,000자로 확인하고 기여·한계만 재평가 | 확인 범위를 표시한 최종 평가 |
| 6. 선정 | 기준을 통과한 후보만 다양성 재정렬. 기본 3편, 강한 추가 후보가 있을 때 최대 5편 | 짧은 읽기 목록 |
| 7. 설명·전달 | 가장 우선하는 1편은 정독 후보, 나머지는 훑어볼 후보. 설정 시각·채널로 전달 | 추천 근거가 있는 메시지 |
| 8. 피드백 | 유용함·관련 없음·이미 알고 있음·근거 부족 등 명시적 응답 저장. 설정 수정 제안은 preview에서만 표시 | 사용자가 검토하는 관심 조정 |

의미 검색에는 설정한 embedding 제공자를 사용하고, 임베딩은 논문 ID·본문 해시·모델별로 캐시한다. 제공자가 없거나 실패하면 수집 검색어·범주로 후보를 압축한 뒤 LLM의 의미 기반 관련성 판정을 사용한다. 이 경우 검색 범위가 제한되었음을 기록하며, 모의 임베딩을 실제 개인화 신호처럼 사용하지 않는다. 50편은 읽기 추천 수가 아닌 내부 평가 상한이다. 주제 수가 바뀌면 이 상한 안에서 주제별 후보 수를 나눈다.

공개 HTML이 없으면 제목·초록으로 평가하고 `초록만 확인`을 표시한다. PDF 전체 분석은 첫 버전에 포함하지 않는다. HTML 확인은 원문 제공자의 공개 URL에서만 하며 시간·크기 제한과 캐시를 적용한다. 접근 실패 때문에 모든 추천이 멈추지는 않는다. LLM 요청 예산이 소진되면 완료된 평가만 사용하고 검사 범위를 표시한다. 점수를 만들어 채우지 않는다.

## 무엇을 높게 평가하는가

| 항목 | 비중 | 높은 평가의 근거 |
| --- | --- | --- |
| 문제 중요도 | 30% | 널리 존재하는 실질적 실패·병목, 여러 환경에 적용되는 원리, 신뢰성·안전성에 큰 영향을 주는 문제 |
| 기여·근거 | 30% | 기존 접근과의 명확한 차이, 구체적 분석·실험·이론 근거, 적용 범위와 한계가 드러남 |
| 연구계 관심 | 25% | HF 반응, 논문 연령을 고려한 S2 인용 등 실제 관측값 |
| 개인 관련성 | 15% | 설정한 주제·우선순위·연구 철학과의 실질적 연결 |

LLM이 작성한 `중요하다`는 설명만으로 중요도 5점을 주지 않는다. 어떤 실패·병목을 해결하며 왜 영향 범위가 넓은지를 근거와 함께 제시해야 한다. 기여 근거 3점은 구체적 기여와 평가 방식이 드러나는 수준, 4점은 범위·비교·한계까지 구체적인 수준, 5점은 확인한 본문에서 강한 근거가 뒷받침되는 수준이다. 초록만 확인한 기여 근거 점수의 상한은 4점이다. 저자가 주장한 결과와 직접 확인한 근거를 구분한다. 미래 영향력이나 재현성을 확정하지 않는다.

관심 신호는 품질과 구분한다. HF 반응은 같은 게시 날짜·넓은 주제의 관측 표본이 10편 이상일 때 백분위로 비교한다. S2 인용은 발표 14일 이상 지난 논문에 대해 연령 구간·넓은 주제의 표본이 10편 이상일 때 인용/일을 비교한다. 표본이 부족하면 원시 수치만 보여주고 점수는 미확인으로 둔다. 여러 유효 신호가 있으면 백분위 점수의 평균을 사용한다. 유명 저자·기관·학회라는 사실이나 여러 사이트에 동시에 등장했다는 사실만으로 별도 가점을 주지 않는다.

기본 통과 기준은 관련성·중요도·기여 근거 각각 3/5 이상과 종합점수 3.5/5 이상이다. 관심 점수가 미확인이면 중요도·기여 근거 각각 4/5 이상을 요구하고 나머지 비중을 비례 재조정한다. 이 기준은 초기 운영에서 조정할 수 있다. 관심이 낮아도 중요도·기여가 강한 신생 연구는 통과할 수 있다.

## 3~5편을 고르는 규칙

- 평가 점수는 0~1로 정규화한다. 통과 후보에서 `0.85 × 평가 점수 − 0.15 × 이미 고른 논문과의 최대 유사도`가 큰 순서로 고른다. PaperFlow의 MMR 다양성 아이디어를 참고한 별도 설정이다.
- 유사도는 사용 가능한 의미 임베딩의 cosine 값을 0~1로 제한해 사용하고, 없으면 평가에서 추출한 문제·방법 개념 집합의 Jaccard 유사도를 사용한다. 문제 설명과 기여 설명의 유사도가 모두 0.90 이상이면 한 편만 고른다. 개념 집합 대체 모드에서는 두 유사도가 모두 0.80 이상인 경우를 적용한다. 같은 문제라도 기여가 다른 논문은 이 중복 규칙으로 배제하지 않는다. 임계값은 설정에서 조정한다.
- 같은 넓은 주제는 하루 최대 2편. 주제가 여러 개인 논문은 주된 기여 주제 하나로 계산한다.
- 기본 3편을 고르되, 최소 종합점수 3.5/5와 다른 기준을 통과한 후보가 부족하면 0~2편이다. 4·5번째는 다양성 규칙과 재정렬 전 종합점수 4/5 이상을 모두 만족해야 한다.
- 인접한 새 방향은 최대 1편까지 포함할 수 있지만 동일한 품질 기준을 통과해야 한다. 빈자리를 채우기 위해 추천하지 않는다.
- 동점에서는 설정한 주제 우선순위, 발견 시각, 논문 ID 순서로 결정한다. safety·reasoning은 후보 단계에서 충분히 검토하며, 품질 기준을 통과한 후보가 있을 때 선정 기회를 확보한다.

## 메시지와 후속 연구

각 논문은 제목·링크와 다음 5개 정보를 짧게 제시한다: **왜 지금 읽을 가치가 있는지 / 핵심 기여와 확인 근거 / 나의 주제와 연결 / 연구계 관심과 한계 / 읽으며 확인할 질문**. 기본 설명은 논문당 5개 짧은 문장, 링크를 제외하고 400자 이내로 한다. 마지막에 `초록 기반` 또는 `본문 일부 확인`을 표시한다. 내부 점수와 탈락 사유는 preview에서 보며, 일일 알림에서는 점수표를 길게 보여주지 않는다.

팔로우한 연구자의 새 논문과 팔로우 논문을 발전시키는 후속 연구는 별도 이벤트 흐름에서 판정한다. 팔로우 대상이라는 이유로 일일 추천 기준을 면제하지 않는다. 일일 추천과 이벤트가 같은 논문이면 한 번 전달한다. 즉시 이벤트 기본 상한 3건/일, 초과분은 다음 다이제스트에 묶는다.

읽지 않음·메시지를 열지 않음·응답 없음은 부정적 피드백으로 취급하지 않는다. `관련 없음`도 그 논문에 대한 응답이며 전체 분야를 자동 배제하지 않는다. 같은 방향의 명시적 피드백이 최소 3회 누적되면 preview가 주제 설명·우선순위 변경을 제안할 수 있다. 사용자가 YAML/CLI에서 적용하기 전에는 프로필을 바꾸지 않는다. 첫 버전은 피드백 저장과 수정 제안을 포함하고, 자동 관심 이동 학습은 이후 범위다.

## 설정과 확인할 동작

사용자가 변경할 값: 주제 설명·우선순위·제외 개념, 후보 수와 평가 예산, embedding 사용 여부, 본문 일부 확인 여부, 평가 비중·통과 기준, 일일 편수·주제 상한, 피드백 제안 사용 여부. 개인 설정과 비밀정보는 공개 저장소에 넣지 않는다.

검증 사례: 관련만 있는 작은 연구 탈락, 인기 있지만 무관한 논문 탈락, 관심 수치 없는 강한 연구 통과, 같은 문제의 유사 논문 한 편만 선정, 충분한 근거 없는 실험 수치 제거, 안전성·추론 후보의 검색 누락 확인, 미열람으로 프로필 불변, 후보 부족 시 3편 강제 충원 없음. 초기 실제 운영에서는 추천 이유와 명시적 피드백을 보고 임계값을 조정한다.
