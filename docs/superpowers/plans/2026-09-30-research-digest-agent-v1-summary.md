# 첫 버전 구현 계획 요약

추천 설계 확정: 2026-09-30. 제품 코드 구현 전이며, 실행 방식은 아직 선택되지 않았다.

## 네 가지 구현 묶음

1. **설정과 수집:** 안내형 CLI·YAML 설정, arXiv·HF·Scholar 메일, 논문 ID 중복 제거와 SQLite 상태.
2. **추천:** 넓은 주제로 최대 50편 압축 → 관련성·중요도·근거·관심 평가 → 상위 8편의 공개 HTML 일부 확인 → 다양성을 고려한 3~5편 선정. 명시적 피드백 저장과 설정 수정 제안.
3. **알림:** 기본 오전 9시 다이제스트와 의미 있는 팔로우 이벤트, 채널별 재시도·중복 억제, 상시 실행·시간대·재시작 복구.
4. **공개:** 예시 설정·설치 문서·오프라인 미리보기·Docker·테스트·CI를 갖춘 GitHub 공개 저장소.

## 유지할 핵심 기준

- 중요도 30%·기여 근거 30%·관측 관심 25%·개인 관련성 15%.
- 관련성·중요도·근거 각각 3/5, 종합점수 3.5/5 이상. 관심 미확인이면 중요도·근거 각각 4/5 이상.
- 기본 3편, 종합점수 4/5 이상인 추가 후보가 있을 때만 최대 5편. 같은 넓은 주제는 최대 2편.
- 인기·유명 저자·학회와 기여의 근거를 구분한다. 미열람·무응답은 관심 감소로 해석하지 않는다.
- 개인 설정·비밀정보는 공개하지 않는다. 첫 버전은 각자가 실행하는 도구다.

## 실행 방식

**Native 추천:** 한 구현자가 작업을 순서대로 연결하고 마지막에 전체 검토를 받는다. 공유 모델과 상태 인터페이스가 많아 연결 작업의 일관성을 유지하기 쉽다.

**Subagent-driven:** 작업마다 구현자와 검토자를 분리한다. 중간 검토가 더 많으며 실행 비용과 시간이 늘어난다.
